# Health Tracker

## 목적 및 개요

- 이 프로그램은 건강 검진 기록을 관리하기 위한 프로그램이다.
- 여러 명의 사용자가 자신만의 기록을 관리할 수 있어야 한다.
- 이 앱은 집 안의 서버에서 동작하며, 외부로는 노출하지 않고, 추후 필요에 따라 VPN을 사용하여 접속하도록 한다.

## 주요 기능

- 사용자 추가/수정/삭제
- 검진 항목 추가/수정/삭제
- 검진 항목별 결과 조회 (그래프 출력)
- 검진 결과 추가/수정/삭제

## 사용자 역할 및 권한

- 사용자는 일반 가족 구성원으로, 검진 항목을 추가하여 검진 결과를 입력한다.
- 사용자가 입력하는 검진 결과는 날짜순이 아닐 수 있으며, 조회시에는 날짜순으로 정렬된다.

## 대상 장비

- 이 앱은 Raspberry PI 5 에서 docker 환경에서 구동되는 웹앱이며, 대상 클라이언트는 브라우저가 탑재된 모든 IT 기기에서 동작해야 한다. 단, 주 동작 기기는 PC 및 모바일 환경이다.

## UI 요구사항

- 최초 접속시 사용자가 없는 경우 사용자 추가 페이지가 노출된다.
- 사용자가 로그인하면 검진 항목들에 대한 가장 최근 검진 결과가 표시되는 카드 정보가 출력된다.
  - 이 화면에서 검진 항목을 검색할 수 있어야 한다.
  - 검진 항목 카드는 기본적으로 항목 이름순(오름차순)으로 정렬되어 표시된다.
    사용자가 표시 순서를 지정하면 그 순서를 따른다. ([003](003-display-order.md))
- 검진 항목 카드를 선택하면 해당 검진 항목에 대한 사용자의 결과 값의 변화를 차트와 표로 표시한다.
- 검진 결과의 조회 기간을 설정할 수 있어야 한다.
- 화면 전환과 뒤로 가기
  - 로그인 / 대시보드 / 항목 상세 / 일괄 입력 화면으로 전환할 때마다 브라우저 history에 한 단계씩 쌓는다.
    브라우저·마우스·휴대폰의 뒤로 가기는 사이트를 벗어나지 않고 이전 화면으로 돌아가며, 앞으로 가기도 동작한다.
  - 화면 안의 `← 목록`·`취소` 버튼은 브라우저 뒤로 가기와 같은 동작이다. (history가 불필요하게 길어지지 않도록)
  - 일괄 입력에 저장하지 않은 값이 있는 상태에서 뒤로 가면 확인 창을 띄우고, 취소하면 값을 유지한 채 그 화면에 머문다.
  - 앱의 첫 화면은 history에 쌓지 않는다. 첫 화면에서 뒤로 가면 브라우저 기본 동작대로 사이트를 떠난다.

## 기능 요구사항

- 사용자 로그인은 이름 선택으로만 가능하게 한다.
- docker 환경에서 실행가능하도록 Dockerfile 및 docker-compose.yaml 파일을 구성한다.
- 사용자 선택 및 로그인 창이 필요함.
- 사용자별로 데이터를 따로 관리할 수 있어야 함.
- 검진 항목은 측정값 유형(숫자/문자열)을 가진다. 숫자형 항목은 판정 구간과 그래프를 제공하고, 문자열 항목은 판정 구간 없이 기록 표로만 관리한다.
- 검진 항목 구간은 숫자형 항목에 한해 1개 이상 입력받아야 함. 구간 이름은 자유 문자열이며, UI는 첫 구간의 기본값으로 '정상'을 제안한다.
- 검진 항목 구간은 추가로 경계, 위험 구간을 입력받을 수 있어야 함.
- 검진 항목 구간 값과 비교하여 검진 결과를 표시할 수 있어야 함.
- 판정 구간마다 표시 색상을 5가지(청록/파랑/주황/빨강/회색) 중에서 사용자가 직접 지정할 수 있어야 함.
- 같은 이름의 검진 항목은 대상 성별이 전체(ALL)인 경우 한 항목만 생성 가능하고, 남성/여성으로 나뉘는 경우 성별당 하나씩 생성 가능해야 함.
- 그래프 출력은 Chart.js를 사용하며, 선 그래프를 적용한다.

## 구현 요구사항

### 백엔드
- Framework: FastAPI (Python 3.12)
- 서버: uvicorn
- 데이터베이스: SQLite
- 배포: Docker (FROM python:3.12-slim)


### 프론트엔드
- 프레임워크:Vanilla JavaScript (프레임워크 없음)
- 차트 라이브러리: Chart.js (chart.umd.min.js)
- 스타일링: CSS (style.css)
- 기타: Service Worker (sw.js) - PWA 지원

### 캐시 정책 (배포 후 새로고침 한 번으로 반영되어야 한다)
- Service Worker는 `/sw.js`로 **루트에서 서빙**해 등록한다. `/static/sw.js`로 등록하면 scope가 `/static/`이 되어
  앱 페이지(`/`)를 제어하지 못한다. (초기 버전의 버그)
- `/`, `/sw.js`, `/static/*` 응답에 `Cache-Control: no-cache`를 붙여 브라우저가 항상 재검증(ETag → 304)하게 한다.
  헤더가 없으면 브라우저가 휴리스틱으로 오래 캐시하고, 일반 새로고침은 문서만 재검증하므로
  **새 index.html + 옛 style.css/app.js**가 섞여 보인다. (설정 메뉴 배포 때 실제로 발생, Ctrl+F5로만 해결됐음)
- Service Worker는 **네트워크 우선, 실패(오프라인)할 때만 캐시**를 쓴다. 집 안 LAN에서 쓰는 앱이라 네트워크가
  거의 항상 되므로 캐시 우선의 속도 이점이 없고, 캐시 우선은 위와 같은 혼합 표시를 만든다.
- API(`/api/*`)는 캐시하지 않는다. 오프라인에서는 마지막 화면 틀만 뜨고 데이터는 보이지 않는다.
- 정적 파일을 바꾸면 `sw.js`의 캐시 버전(`CACHE`)을 올린다.

## Database 구조

### users: 사용자 Table

- id (INT, PK): 사용자 ID
- name (VARCHAR, UNIQUE): 사용자 이름 (동명이인은 별명/이니셜로 구분)
- birth_date (DATE): 나이 계산을 위한 생일
- gender (ENUM): 성별(M, F)

### checkup_items: 검진 항목 Table

- id (INT, PK): 항목 ID
- item_name (VARCHAR): 검진 항목 이름
- unit (VARCHAR): 측정 단위
- value_type (ENUM): 측정값 유형 (NUMBER, TEXT)
  - NUMBER: 측정값을 숫자로 입력받는 항목 (예: 공복혈당, 혈압)
  - TEXT: 측정값을 문자열로 입력받는 항목 (예: 요잠혈의 음성/양성)
  - TEXT 항목은 판정 구간(checkup_item_ranges)을 가질 수 없으며, 그래프 없이 기록 표로만 조회한다.
  - 검진 결과가 이미 존재하는 항목의 value_type은 변경할 수 없다.
- target_gender (ENUM): 대상 성별 (ALL, M, F)
  - 검진 항목의 target_gender에 따라 로그인한 사용자의 성별에 맞게 필요 없는 항목은 숨긴다.
- UNIQUE(item_name, target_gender)
  - 같은 이름의 검진 항목은 target_gender가 ALL인 경우 하나만 생성할 수 있다.
  - 같은 이름의 검진 항목을 남성(M)/여성(F)으로 나누는 경우 성별당 하나씩 생성할 수 있다.
  - target_gender가 ALL인 항목과 같은 이름의 M/F 항목은 공존할 수 없다.
    (성별별로 나누려면 기존 ALL 항목의 target_gender를 먼저 수정해야 한다.)

### checkup_item_ranges: 검진 항목 구간 Table

- id (INT, PK): 검진 항목 구간 ID
- item_id (INT, FK): checkup_items.id 참조
- min_value (FLOAT): 구간 최소값
- max_value (FLOAT): 구간 최대값
- judgement_level (VARCHAR): 판단 수준(정상, 경계, 위험 등)
  - 판단 수준은 검진 항목에 따라 다른 문자열로 표현될 수 있다. (예, 혈압의 경우 저혈압, 정상, 고혈압 등)
  - 판단 수준은 검진 항목당 판단 수준별로 하나씩만 존재해야 함.
  - 조회시마다 실시간 판단하는 기준이 된다.
  - 판정 구간이 하나만 정의된 항목은 (이름과 무관하게), 그 범위를 벗어나는 값을 '위험'(danger 색상)으로 판정하여 표시한다.
    (구간이 2개 이상 정의된 항목은 어떤 구간에도 속하지 않는 값에 판정을 표시하지 않는다.)
- color (ENUM): 구간 표시 색상 (ok, lowish, warn, danger, etc 중 하나)
  - ok=청록, lowish=파랑, warn=주황, danger=빨강, etc=회색
  - 사용자가 구간 생성/수정 시 직접 지정한다. (UI는 판정 수준 이름의 키워드로 초기값을 제안할 수 있다)
  - 판정 배지, 그래프의 구간 밴드, 그래프 데이터 포인트 색상에 일관되게 적용된다.

### checkup_results: 검진 결과 Table

- id (INT, PK): 검진 결과 ID
- user_id (INT, FK): users.id 참조
- item_id (INT, FK): checkup_items.id 참조
- date (DATE): 측정 날짜
- value (FLOAT, NULLABLE): 숫자형(NUMBER) 항목의 측정 수치
- value_text (VARCHAR, NULLABLE): 문자형(TEXT) 항목의 측정값
  - 항목의 value_type에 따라 value 또는 value_text 중 정확히 하나만 채워진다. (CHECK 제약)
- note (VARCHAR): 비고
- UNIQUE(user_id, item_id, date)
