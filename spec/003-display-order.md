# 003. 검진 항목·카테고리 표시 순서

- 상태: 구현됨
- 작성일: 2026-10-06
- 기준 문서: [design.md](design.md), [001](001-item-category.md), [002](002-batch-result-input.md)

## 목적

검진 결과지는 카테고리와 항목이 정해진 순서(예: 간기능 안에서 AST → ALT → γ-GTP)로 나온다.
이름순(ALT → AST)으로는 결과지를 보며 위에서 아래로 입력하기 불편하다.
사용자가 카테고리와 항목의 표시 순서를 직접 정할 수 있게 한다.

## 결정 사항

| 항목 | 결정 |
| --- | --- |
| 적용 범위 | 대시보드와 일괄 입력 화면 모두. 순서는 하나만 둔다 |
| 대상 | 카테고리 순서 + 카테고리 안의 항목 순서 (001의 범위 밖 항목을 여기서 다룸) |
| 기본값 | 순서를 정하지 않은 것은 지금처럼 이름순. 새로 만든 항목·카테고리는 자기 자리(카테고리 끝)에 이름순으로 붙는다 |
| UI | 대시보드 헤더의 `설정 ▾` 메뉴 → `순서 편집` → ▲▼ 버튼 모달에서 옮기고 한 번에 저장 |
| 공유 범위 | 항목·카테고리와 같이 모든 사용자가 공유 |

design.md의 "카드는 항목 이름순으로 정렬"은 "기본 이름순, 사용자가 지정하면 그 순서"로 완화한다.

## 기능 요구사항

### 정렬 규칙
- 카테고리: `sort_order` 오름차순 → 없는 것은 뒤에 이름순. `미분류`는 항상 마지막.
- 항목: 카테고리별로 묶은 뒤, 카테고리 안에서 `sort_order` 오름차순 → 없는 것은 뒤에 이름순.
- 이 순서를 대시보드 섹션·칩·카드, 일괄 입력 섹션·줄, 항목 폼의 카테고리 선택에 동일하게 쓴다.
- 대시보드 검색·칩 필터는 순서에 영향을 주지 않는다 (걸러낼 뿐).

### 순서 편집 모달
- 대시보드 헤더의 `설정 ▾` 메뉴 → `순서 편집`으로 연다.
- **모든** 카테고리와 **모든** 항목을 보여 준다. 로그인 사용자 성별로 숨긴 항목도 포함한다
  (순서는 공유이므로). 성별 전용 항목은 지금처럼 성별 태그를 붙인다.
- 카테고리 줄과 항목 줄에 ▲▼ 버튼을 둔다.
  - 카테고리 ▲▼: 카테고리 전체(소속 항목 포함)가 함께 움직인다. `미분류`는 움직일 수 없다.
  - 항목 ▲▼: 같은 카테고리 안에서만 움직인다. 카테고리를 바꾸는 것은 항목 폼에서 한다.
  - 맨 위의 ▲, 맨 아래의 ▼는 비활성.
- `저장`을 누르면 화면에 보이는 순서대로 전체를 한 번에 저장하고 모달을 닫은 뒤 대시보드를 갱신한다.
- `취소`는 아무것도 저장하지 않는다.
- 카테고리가 하나도 없으면 항목 목록만 보여 준다.

## 데이터베이스

### checkup_categories (변경)
- sort_order (INT, NULLABLE): 표시 순서. NULL이면 이름순으로 뒤에 붙는다.

### checkup_items (변경)
- sort_order (INT, NULLABLE): 카테고리 안에서의 표시 순서. NULL이면 이름순으로 뒤에 붙는다.
  - 값은 전체 항목에 걸쳐 저장 순서대로 0, 1, 2, …를 매긴다. 카테고리 안에서만 비교하므로
    카테고리가 바뀌어도 그 안에서의 상대 순서는 유지된다.

### 기존 DB 마이그레이션
001과 같은 방식. `init_db`에서 `PRAGMA table_info`로 두 테이블의 `sort_order` 유무를 확인해 없으면
`ALTER TABLE … ADD COLUMN sort_order INTEGER`를 실행한다. 기존 데이터는 NULL(이름순)이다.

정렬 SQL: `ORDER BY sort_order IS NULL, sort_order, name COLLATE NOCASE, id`

## API

### 순서 저장 (신규)
- `PUT /api/order`
  - body: `{category_ids: [id, …], item_ids: [id, …]}`
  - 각 배열의 인덱스를 `sort_order`로 저장한다. 한 트랜잭션으로 처리한다.
  - 중복 id가 있으면 422, 존재하지 않는 id가 있으면 404.
  - 배열에 없는 카테고리·항목의 `sort_order`는 건드리지 않는다.
  - 응답: 204

### 기존 API (변경)
- `GET /api/categories`, `GET /api/items`, `GET /api/users/{uid}/summary`의 정렬이 위 정렬 규칙을 따른다.
  응답에 `sort_order`가 포함된다.
