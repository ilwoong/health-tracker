# 001. 검진 항목 카테고리

- 상태: 구현됨
- 작성일: 2026-10-06
- 기준 문서: [design.md](design.md)

## 목적

검진 항목이 늘어나면 대시보드에서 원하는 항목을 찾기 어렵다.
각 검진 항목에 상위 카테고리(예: 혈액, 간기능, 신장기능)를 지정해 묶어서 보여 준다.

## 결정 사항

| 항목 | 결정 |
| --- | --- |
| 카테고리 관리 | 사용자가 UI에서 직접 추가/수정/삭제 (`checkup_categories` 테이블) |
| 계층 | 1단계만 (카테고리 안에 하위 카테고리 없음) |
| 공유 범위 | 검진 항목과 동일하게 모든 사용자가 공유 |
| 지정 여부 | 선택. 카테고리가 없는 항목은 '미분류'로 표시 |
| 대시보드 | 카테고리별 섹션 + 상단 필터 칩 |
| 섹션 순서 | 카테고리 이름 오름차순 (직접 순서 지정 없음) |
| 관리 진입점 | 대시보드 헤더의 `카테고리 관리` 버튼 |
| 기본 카테고리 | 만들지 않음. 처음에는 카테고리 없이 시작 |
| 일괄 입력 화면 | 카테고리별 섹션 제목만 붙임. 필터 칩 없음 |

## 기능 요구사항

### 카테고리 관리
- 카테고리를 추가/수정(이름 변경)/삭제할 수 있다.
- 카테고리 이름은 앞뒤 공백을 제거한 뒤 비교하며, 비어 있을 수 없고 중복될 수 없다.
- '미분류'는 실제 카테고리가 아니라 카테고리가 없는 항목을 묶어 보여 주는 표시용 이름이다.
  같은 이름의 카테고리는 만들 수 없다.
- 카테고리를 삭제하면 그 카테고리에 속한 검진 항목은 삭제되지 않고 '미분류'가 된다.
  삭제 전 확인 창에 영향을 받는 항목 수를 표시한다.

### 검진 항목
- 검진 항목 추가/수정 폼에서 카테고리를 선택할 수 있다. 기본값은 '미분류'(없음)이다.
- 기존 검진 항목은 모두 '미분류'로 시작한다.

### 대시보드
- 카드를 카테고리별 섹션으로 묶어 표시한다.
  - 섹션 순서: 카테고리 이름 오름차순, '미분류'는 항상 마지막 (사용자 지정 순서는 [003](003-display-order.md))
  - 섹션 안의 카드 순서: 지금처럼 항목 이름 오름차순 (사용자 지정 순서는 [003](003-display-order.md))
- 검색창 아래에 필터 칩을 둔다: `전체` + 카테고리별 칩 + `미분류`
  - 한 번에 하나만 선택한다. 기본값은 `전체`.
  - 특정 칩을 선택하면 그 카테고리 섹션만 보인다.
- 검색어와 필터 칩은 함께 적용된다 (AND).
- 숨김 규칙
  - 섹션: 어떤 이유(성별, 검색어, 칩 선택)로든 표시할 카드가 없으면 숨긴다.
  - 칩: 로그인 사용자의 성별 기준으로 항목이 하나도 없는 카테고리의 칩만 숨긴다.
    검색어는 칩 표시에 영향을 주지 않는다. `미분류` 칩도 같은 규칙을 따른다.
- 로그인 사용자에게 보이는 항목 중 카테고리가 있는 것이 하나도 없으면,
  섹션 제목과 필터 칩을 표시하지 않고 지금과 같은 화면을 보여 준다.
- 칩 선택 상태는 대시보드에 다시 들어올 때마다 `전체`로 초기화한다.

### 상세 화면
- 항목 이름 근처에 카테고리 이름을 표시한다. (미분류면 표시하지 않음)

### 일괄 입력 화면 ([002](002-batch-result-input.md))
- 항목 줄을 대시보드와 같은 순서(카테고리 순서, `미분류`는 마지막)로 묶고 섹션 제목을 붙인다.
  섹션 안의 순서와 Enter로 다음 항목 이동은 지금과 같다.
- 필터 칩은 두지 않는다. 모든 항목이 항상 화면에 있어야 입력값이 숨겨지는 일이 없다.
- 대시보드와 같은 조건(카테고리가 있는 항목이 없음)이면 섹션 제목을 표시하지 않는다.

## 데이터베이스

### checkup_categories: 검진 항목 카테고리 Table (신규)

- id (INT, PK): 카테고리 ID
- name (VARCHAR, UNIQUE): 카테고리 이름
  - 조회 시 정렬은 검진 항목과 같이 `COLLATE NOCASE` 오름차순

### checkup_items (변경)

- category_id (INT, FK, NULLABLE): checkup_categories.id 참조 — 컬럼 추가
  - NULL이면 미분류
  - 카테고리 삭제 시 NULL로 변경 (ON DELETE SET NULL)

### 기존 DB 마이그레이션

새 DB에서는 `init_db`의 `CREATE TABLE checkup_items`에 `category_id` 컬럼이 포함된다.
그러나 현재는 `CREATE TABLE IF NOT EXISTS`만 사용하므로, 이미 만들어진 health.db에는 새 컬럼이 추가되지 않는다.
앱 시작 시(`init_db`) 다음을 **이 순서로** 처리한다. (`ALTER`의 FK 대상이므로 카테고리 테이블이 먼저 있어야 한다)

1. `checkup_categories` 테이블이 없으면 생성 (`CREATE TABLE IF NOT EXISTS`로 충분)
2. `checkup_items`에 `category_id` 컬럼이 없으면
  `ALTER TABLE checkup_items ADD COLUMN category_id INTEGER REFERENCES checkup_categories(id) ON DELETE SET NULL` 실행
  - `PRAGMA table_info(checkup_items)`로 컬럼 존재 여부 확인
  - 기존 데이터는 모두 NULL(미분류)이 되므로 데이터 변환은 필요 없다.

## API

### 카테고리 (신규)
- `GET /api/categories` — 이름 오름차순. 각 카테고리에 속한 항목 수(`item_count`) 포함
- `POST /api/categories` — body: `{name}`. 이름이 비어 있거나 '미분류'이면 422, 중복이면 409
- `PUT /api/categories/{id}` — body: `{name}`. 규칙은 POST와 동일
- `DELETE /api/categories/{id}` — 소속 항목은 미분류로 변경

### 검진 항목 (변경)
- `POST /api/items`, `PUT /api/items/{id}` body에 `category_id` (nullable) 추가
  - 존재하지 않는 category_id이면 422
- `GET /api/items`, `GET /api/users/{uid}/summary` 응답의 각 항목에 `category_id` 추가
  - 카테고리 이름은 프론트엔드가 `GET /api/categories` 결과로 매핑한다.

## UI

- 대시보드 헤더에 `카테고리 관리` 버튼을 추가하고, 모달에서 목록/추가/이름 변경/삭제를 처리한다.
- 항목 폼의 카테고리 선택: `<select>` (미분류 + 카테고리 목록)
